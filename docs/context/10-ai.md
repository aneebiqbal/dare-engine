# 10 — AI

One client, one interface: `api/app/llm/base.py` (`LLM.complete_json`). The API
selects a provider in `api/app/llm/__init__.py:get_llm`. Every call asks for
JSON, validates it against a schema, retries once on invalid output, and falls
back to a non-AI path with a visible notice. Each call writes an `ai_usage` row
(`api/app/ai.py:run_ai`).

## Call sites

| Page | Route | `kind` | Prompt | Expected JSON | Fallback |
| --- | --- | --- | --- | --- | --- |
| Today | `POST /ai/suggest` | `suggest` | inline in `api/app/ai.py` | `{cards:[MissionCard]}` (max 3) | next three approved missions |
| Mission editor | `POST /ai/mission-editor` | `editor` | inline | `{hook_text, win_condition, title_spoiler}` | unchanged card |
| Clips | `POST /ai/clip-review` | `clip_review` | inline (transcript excerpt) | `{hook_line, score, weaknesses[], beats[]}` | score from transcript length |
| Export | `POST /ai/export` | `export` | inline | `{titles[3], description, tags[]}` | question + hook + mode |
| Results | `GET /ai/results-summary` | `results_summary` | inline (by_type + top clips) | `{summary}` | best type from the numbers |
| Admin pool | `POST /ai/pool-review` | `pool_review` | inline | `{merged[], policy_flags[]}` | questions as typed |
| Help | `POST /ai/help` | `help` | `api/app/help_guide.md` appended to the system prompt | `{answer}` | "AI help is unavailable" |
| Admin pool | `POST /admin/questions` | `cards` | `SYSTEM` in `api/app/missions.py` | `{cards:[MissionCard]}` | one plain card per question |
| Worker beats | `worker/clip/beats.py` | — | inline | `{setup:[{start,end}]}` | word density |

The worker beat call uses the **legacy Gemini client** in `worker/clip/llm.py`
when `GEMINI_API_KEY` is set; it does not use the new client and is not logged to
`ai_usage`. In the default run `GEMINI_API_KEY` is unset, so `get_llm()` returns
`None` and word density is always used.

## Provider configuration

| Variable | Purpose |
| --- | --- |
| `LLM_PROVIDER` | `openai` (OpenAI-compatible) / `recorded` / `stub` |
| `LLM_BASE_URL` | e.g. `https://opencode.ai/zen/v1` or `https://api.x.ai/v1` |
| `LLM_API_KEY` | bearer key (never printed; `GET /admin/ai-config` shows only `key_present`) |
| `LLM_MODEL` | model id |
| `LLM_TIMEOUT` | seconds (default 60) |
| `LLM_RECORDED_RESPONSE` | recorded file for CI |

`api/app/llm/openai_compat.py` POSTs `{base}/chat/completions` with
`Authorization: Bearer`, `temperature: 0`, `response_format: {"type":"json_object"}`.
Verified endpoints: OpenCode Zen `https://opencode.ai/zen/v1` (model ids from
`https://opencode.ai/zen/v1/models`) and xAI Grok `https://api.x.ai/v1`.

Providers:
- `openai` → `OpenAICompatibleLLM` (urllib, no SDK).
- `recorded` → `RecordedLLM` replays `api/app/llm_recorded.json`, keyed by
  `kind` (`cards`, `suggest`, `editor`, `clip_review`, `export`,
  `results_summary`, `pool_review`, `help`).
- `stub` → raises `LLMError`.
- `api/app/llm/gemini.py` is **dead code** (no route selects it).

## Live vs recorded

- **Live:** never run. No API key exists (`PROGRESS.md` Gate 0). Nothing in the
  acceptance suite calls a live model.
- **Recorded:** `LLM_PROVIDER=recorded` is the compose default and is what
  `make accept`/`make web-accept` use. All seven page rows and the mission
  writer pass with recorded answers.
- **Worker beats:** always the word-density fallback in the default run.

## Voice-over model

- Package: `piper-tts>=1.8.0` (`worker/requirements.txt`).
- Voice: `en_US-amy-medium` from `rhasspy/piper-voices` on Hugging Face,
  downloaded by `make voice` (`worker/app/voice.py`) into `/data/voices`.
- Model file size: 63,221,984 bytes (`en_US-amy-medium.onnx`).
- Licence: the `rhasspy/piper-voices` README front matter says `license: mit`
  (checked today). Piper itself is MIT (`rhasspy/piper`). Individual voice cards
  vary; the UI tells the creator their own voice is safer for monetisation.
- The voice-over pipeline ran end to end on the stand-in
  (`tests/acceptance/test_sprint6_voice.py`, 2 passed).
